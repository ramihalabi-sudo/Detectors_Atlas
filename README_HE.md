# Detector Atlas · Automatic Technology Watch

אפליקציית קטלוג EO שמציגה התראה בזמן הכניסה לאתר על גלאים שהתגלו לאחרונה בעמודי מוצרים רשמיים. בניגוד לקובץ HTML מקומי, **מעקב אוטומטי דורש פרסום של האפליקציה והפעלת סורק בענן**. החבילה כוללת סורק Python ו־GitHub Actions, ללא מפתח API או שרת בתשלום.

## הפעלה על GitHub Pages

1. פתח חשבון GitHub וצור Repository חדש (למשל `detector-atlas`). מומלץ ציבורי כדי להשתמש בחינם ב־Pages וב־Actions בהתאם למגבלות התוכנית.
2. חלץ את קובץ ה־ZIP והעלה את **תוכן התיקייה**, כולל `index.html`, `data/`, `watcher/`, `requirements.txt`, ואת התיקייה הנסתרת `.github/workflows/`. אל תעלה רק את ה־HTML.
3. ב־Repository היכנס ל־**Settings → Actions → General → Workflow permissions** ואפשר ל־Actions הרשאת **Read and write permissions** (אם המדיניות מאפשרת). אשר ש־Actions פעיל, ושה־Pages מוגדר ל־GitHub Actions לפני ההרצה הראשונה.
4. היכנס ל־**Actions → Detector Atlas - scan manufacturer catalogs → Run workflow**. ההרצה הראשונה בונה נקודת בסיס של דגמים קיימים, ולא תציג אותם בטעות כהשקה חדשה. אם חלק מהאתרים לא מאפשרים סריקה, יופיע סטטוס Unavailable.
5. ב־**Settings → Pages** בחר **Build and deployment → Source: GitHub Actions**. הרץ שוב את ה־workflow במידת הצורך ופתח את כתובת האתר שתיווצר, לדוגמה `https://USERNAME.github.io/detector-atlas/`.
6. מכאן ואילך ה־workflow מנסה לסרוק כל **6 שעות**, ואז מפרסם `data/live.json`. כשנכנסים לאתר, או לוחצים **Check online updates**, הדפדפן טוען את הקובץ המעודכן.

> ב־GitHub Actions ההרצות המתוזמנות הן best effort ועלולות להתעכב או להיפסק לפי מדיניות GitHub. סריקה כל 6 שעות אינה התרעה מיידית מרגע שהיצרן פרסם מוצר.

## הפעלה במחשב מקומי

אפשר לפתוח `index.html` לצפייה בקטלוג הקיים. אם אין פרסום פעיל, לא יתבצע מעקב אוטומטי אחרי יצרנים.

אם יש אתר GitHub Pages פעיל, אפשר להזין תחת **Technology Watch → Feed URL** את הכתובת המלאה של `data/live.json` שהתפרסם ב־Pages. אם הדפדפן מונע CORS בקובץ מקומי, פתח את האתר מ־GitHub Pages עצמו, או הרץ שרת מקומי:

```bash
python -m http.server 8000
```

ואז היכנס ל־`http://localhost:8000` (השרת המקומי לא סורק את היצרנים בעצמו; הוא רק מציג את הנתונים).

## איך מזוהים דגמים חדשים

- לכל יצרן מוגדר מקור רשמי, אופן גילוי דגמים וקריטריון תקינות בסיסי ב־`watcher/sources.json`.
- בסריקה **הראשונה שהצליחה** לכל מקור נשמרת נקודת בסיס; לא נוצרת הודעת "NEW" עבור קטלוג ישן.
- החל מהסריקה הבאה, קישור מוצר חדש או מספר דגם חדש מזוהה ונבדק. הסורק מנסה לקרוא מפרטים מתוך עמוד המוצר או תיאור רשמי. ערכים שלא נמצאו נשארים ריקים.
- ההתראה מפרידה בין **תאריך גילוי על ידי הסורק** לבין *תאריך השקה*, שלא בהכרח מפורסם.
- אם הדגם עבר לעמוד אחר או מקור חסום, המערכת אינה קובעת שהדגם הופסק.
- המשתמש רואה בממשק סטטוס של כל מקור וקישור למפרט המקורי, ויכול לסמן הודעות כנקראו. סימון נקראו נשמר **בדפדפן הספציפי** באמצעות localStorage (לא מסונכרן בין מכשירים).

## יצרנים במעקב

בקובץ ההגדרות יש מקורות מחברות SCD, LYNRED, IRnova, GSTiR, AIM, NIT, Gpixel, Hamamatsu, Sony, Teledyne FLIR OEM, Teledyne e2v, onsemi ו־SWIR Vision Systems. זהו ניטור **מיטב המאמצים** של דפי מוצרים פומביים, ואינו מבטיח כיסוי מוחלט של כל החברות או גילוי כל גרסת גלאי. במיוחד, אתרים דינמיים או מוגני Bot עשויים לדרוש התאמת סורק ייעודית.

## שינוי תדירות

בקובץ `.github/workflows/watch.yml` השורה `cron: '17 */6 * * *'` מפעילה סריקה כל 6 שעות ב־UTC. אפשר לשנות לפי הצורך, בכפוף למגבלות GitHub ולהתחשבות בתעבורת היצרנים.

## אימות ודיוק הנדסי

הפרמטרים המופקים אוטומטית הם **מועמדים לבדיקת מהנדס**, ולא ערכים מאושרים לאפיון, ATP או TRM. כדי לא לייצר מידע שגוי, המערכת אינה מסיקה התאמת מקרר רק לפי דגם, אינה מעריכה באופן אוטומטי טווח אורכי גל לפי MWIR/LWIR, ואינה משלימה ערכי NETD או QE שאינם מפורשים. אין להניח ש־HFM ו־XBn הם אותו סיווג.

לכל שורה יש `source_url` וסטטוס. את מקור המפרט יש לקרוא לפני שימוש הנדסי, ולוודא תנאי בדיקה (F/#, טמפרטורה, קצב פריימים, מקוררת/לא מקוררת). הפרסומים הציבוריים לא בהכרח כוללים נתוני מקרר, משך חיים, QE או תאריך השקה.

## קבצים עיקריים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה ומסך Technology Watch |
| `data/catalog.json` | הקטלוג הראשי (201 רשומות בתחילת העבודה) |
| `data/live.json` | קטלוג, התראות ומצב מקורות לפרסום באתר |
| `data/source_state.json` | זיכרון הסורק, נקודות בסיס והיסטוריית התראות |
| `watcher/sources.json` | כתובות יצרן, דפוסי דגמים ואופן הסריקה |
| `watcher/update_catalog.py` | זיהוי שינויים וחילוץ פרמטרים |
| `.github/workflows/watch.yml` | סריקה מתוזמנת ועדכון Git |
| `tests/test_watcher.py` | בדיקות גילוי דגמים ותרחישי כשל |

## הרצה ובדיקות ידניות

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python watcher/update_catalog.py --root .
```

שימו לב: הרצת הסורק מחוץ ל־GitHub תעדכן קבצים מקומיים בלבד, ולא תפרסם אותם אוטומטית לאתר.
